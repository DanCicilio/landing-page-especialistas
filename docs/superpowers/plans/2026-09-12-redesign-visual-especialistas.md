# Redesenho Visual da Landing Page (Magic UI + Aceternity) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static Tailwind gradients/animations across every section of the landing page with Magic UI and Aceternity UI motion components, apply the approved indigo/purple + amber-accent palette, and eliminate the PT/EN content duplication — without changing any copy.

**Architecture:** Each landing-page section becomes its own component in `components/sections/`, fed by a single PT/EN content dictionary (`lib/i18n/content.js`), and composed by the two thin page files (`app/page.jsx`, `app/en/page.jsx`). Motion primitives come from Magic UI and Aceternity UI, installed locally via the shadcn CLI registry system (free, copy-paste model, no vendor lock-in) into `components/ui/`.

**Tech Stack:** Next.js 14 (App Router, JS/JSX, no TypeScript), Tailwind CSS 3, shadcn CLI (registry installer only — this project does not adopt full shadcn/ui styling conventions beyond what Magic UI/Aceternity require), Framer Motion (installed as a dependency of the Magic UI/Aceternity components).

## Global Constraints

- No copy/content changes — every PT and EN string must match what's currently live in `app/page.jsx` and `app/en/page.jsx` exactly.
- No new sections, no SEO/analytics work, no use of 21st.dev (deferred per project decision).
- Color tokens: `primary` (#4f46e5, indigo-600), `primary-dark` (#3730a3, indigo-800), `secondary` (#9333ea, purple-600), `accent` (#f59e0b, amber-500), `accent-dark` (#d97706, amber-600). `accent`/`accent-dark` are used **only** on primary call-to-action buttons (never on decorative/badge elements).
- Preserve the existing env vars used by the contact links exactly: `NEXT_PUBLIC_DAN_WHATSAPP`, `NEXT_PUBLIC_DAN_EMAIL`, `NEXT_PUBLIC_PRI_WHATSAPP`, `NEXT_PUBLIC_PRI_EMAIL`.
- Do not `git push` at any point in this plan — every task commits locally only. Pushing (which triggers a Vercel deploy) requires explicit user confirmation outside this plan.
- All new files are `.jsx` (the project has no TypeScript config); if `npx shadcn@latest init` or `add` generates `.tsx` files, rename them to `.jsx` and strip type annotations before wiring them in (verify in the step that reads the generated file).

```js
// lib/i18n/verify-content.mjs
import { content } from './content.js'

function keys(obj) {
  return Object.keys(obj).sort().join(',')
}

function walk(a, b, path) {
  if (Array.isArray(a)) {
    if (a.length !== b.length) throw new Error(`Array length mismatch at ${path}`)
    a.forEach((item, i) => walk(item, b[i], `${path}[${i}]`))
    return
  }
  if (a && typeof a === 'object') {
    const ka = keys(a)
    const kb = keys(b)
    if (ka !== kb) throw new Error(`Key mismatch at ${path}: pt=${ka} en=${kb}`)
    Object.keys(a).forEach((k) => walk(a[k], b[k], `${path}.${k}`))
  }
}

walk(content.pt, content.en, 'content')
console.log('OK: pt and en have identical structure')
```
